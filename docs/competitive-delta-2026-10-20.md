> 框架、五类记忆、生态位判断不重复，读那份。
> 数据口径：`awesome-dsh-plugin.com/plugins.json`，目录快照 `updated=2026-10-19`，下载窗口 `2026-09-20 ~ 2026-10-19`。

## 0. 一页结论

1. **供给还在加速。** `memory` 分类从 263 → **266**，近 7 天新增 **59 个**（一个月前是 60 个/月，现在是一周的量）。
2. **头部换人了。** 上次点名的两家治理派掉出前 15：`memento` #16（5,972）、`memoir` #26（4,052）。
   顶上来的是新面孔：`Veyra`（10-15 上架，5 天 9,334 冲到 #11）、`annkun`（10-16，7,859，#12）。
3. **「压缩后召回」两家同周上线，但那是架构逼出来的补丁，不是先进。** `meow` 与 `dsh-soul-md` 的长期记忆都是**消息**
   （plugin snapshot / 追加消息），压缩会把它们吃掉，所以必须回注。我们的简报是 **system prompt 段**
   （`promptCtx.systemPrompt.section`，`lib/index.js:726`），压缩不动它——**我们不用抄形状**，只需补「尾部召回被吃掉」那一小块。
4. **竞争焦点从「记得多」转向「控制权」。** 窗口级记忆门控、Agent 不可代审批、候选不进仓库、能力声明与红线审计——
   这四件都是「让用户敢开」，不是「让模型记得更多」。我们也该往这边挪一点。
5. **我们的位置没变，但更危险。** 仍是 #156、`downloads/version` 仍是 `null`、目录里的 install 命令还指着 **v0.5.1** 的
   tarball（我们已经在 0.6.0）。头部在跑，我们在原地。

一句话：**这一个月别人补的是「压缩后的连续性」和「用户手里的开关」。前者我们架构上已经赢了一半（只差尾部召回），
后者是真缺的，而且补起来不破坏字节稳定。**

## 3. 值得抄的五条

排序按「效果 ÷ 成本」，每条都标注了和我们红线的冲突检查——**有些借鉴会直接踩自己的红线，那种宁可抄一半**。

### P0-1 索引行带日期（抄 annkun）

**机制**：索引每行带 `YYYY-MM-DD`，模型在注入时自己判断「这条是三天前还是三个月前」，而不是靠正文猜。

**落点**：`lib/index.js` 的 `renderBriefingStatic` 索引分支（`- ${pin}[${label}] ${title}${tags} (${id})`）。

**红线冲突（关键）**：日期必须取 **`createdAt`**，**绝不能取 `updatedAt`**——`markUsed` 会刷 `updatedAt`，
一用它简报就逐轮变化，C4 当场破。`createdAt` 不可变，字节稳定成立。

**验收**：`briefing-stability` 的「同一会话跨 1.5s + useCount 增长逐字节相同」仍绿；`store` 的简报快照按新格式更新。

**成本**：低（改 1 行 + 2 处断言）。**本轮性价比最高的一条。**

> 落地进度（2026-10-20）：已进代码。`lib/index.js` 新增 `recordDay()`，index / full 两个分支都带日期戳；
> `test/activate.test.mjs` 加了两条断言（格式 + 日期等于创建当天）；README 的索引行示例同步。
> `briefing-stability` 的「useCount 增长仍逐字节相同」照旧绿——它现在同时是「别把 updatedAt 放进来」的守卫。

---

### P0-2 窗口级门控（抄 meow，但只能抄一半）

**机制**：自动注入 / 自动整理两个开关；**决议顺序 会话 > 工作区 > 全局**（soul-md 用同一套思路管人设卡）；
`disabledWorkspaces` 路径归一精确匹配，命中即读/写/整理全拒。

**我们能做到哪**：meow 挂在**会话「…」菜单**，soul-md 有**会话切换器**。我们目前只注册了 `settings.section` 一个座位，
没有会话菜单项。所以第一版**只做全局三开关 + 工作区停用名单**（纯 Config，零 UI），
会话级等确认宿主是否给第三方那个座位再动——**别先按 meow 的形状设计，我们没有那个入口**。

**最小实现**：`Config` 加 `disabledWorkspaces: string[]`（默认空）+ `autoInject` 注入总闸（默认开）；
读取点四处：`briefingText` 入口、`scheduleRecall` 与 `noteToolPaths`、自动提炼的触发块
（`turn/end` 里 `cwd` 归一之后）。名单项用 `normalizeRoot` 做精确匹配。

**验收**：命中停用名单的工作区，简报为空但**不注入空段**（见下），工具仍可用（「只用工具」档）；改配置无需重启。

**红线冲突（关键）**：**关掉注入必须是「不注入」，不是「注入一个空段落」**——空段也会改变提示字节，
直接违反 C4 字节稳定。这条要在实现时写死在入口判断里，不要靠下游过滤。

**成本**：中低（Config + 4 处判断 + 6 条断言）。

> 落地进度（2026-10-20）：已进代码，但**没有照原计划造三个布尔**——`autoCapture` 本来就是「自动整理」开关，
> 再包一层 `captureGate` 是冗余。最终收敛成 `autoInject`（注入总闸）+ `disabledWorkspaces`（停用名单）。
> 停用名单挡「自动」两件事：注入与自动提炼；**手动 `memory` 读写仍放行**（与 meow 的「读写全拒」取向不同，
> 理由写在 README：显式意图静默失败会让模型反复重试）。
> 面板在「设置 → 记忆」顶部加了 `autoInject` 开关；名单本身只走 config / `settings.json`（数组不硬塞进表单）。

### P1-1 压缩后的尾部召回补偿（抄 meow / soul-md，但只抄我们真丢的那块）

**先厘清我们到底丢了什么**：简报走 `promptCtx.systemPrompt.section`（`lib/index.js:726`），是**系统提示段**，
压缩只动消息，不动它——**所以压缩后模型仍然看得见简报与画像**。真正被吃掉的是**消息级的尾部召回**
（`TAIL_SOURCE_KIND` 的 user 消息）和之前查过的正文。这比 meow / soul-md 的处境轻得多：他们的记忆本身就是消息。

**结论**：不要照抄「整块回注」，只补一条**一次性尾部**：压缩后下一轮，把本会话查过的 2~3 条正文再发一次。

**最小实现**

1. 新结构 `sessionSeen: Map<sessionId, string[]>`（上限 20，LRU）——在 `injectTailRecall` 成功、`markOpened` 时累加。
   现有 `sessionRecalls` 只存**最近一轮**（`previous` 仅用于排重），拿不到历史，必须新开一个。
2. 已有的 `compaction/*` 分支（`lib/index.js:1317`）里置 `sessionReinject.set(sessionId, { at })`。
3. 下一个 `agent/pre-step` 命中标记且未补偿过：取 `sessionSeen` 最近 3 条正文，走现有 splice；发完删标记。
   `tailAlreadyInSession` 保证重试/续跑不会重复。

**验收**：压缩后紧接一轮出现补偿块，下一轮不再出现；系统提示字节不变（只加消息，不动 section）；不新增模型调用。

**成本**：低（~50 行 + 3 条断言）。**价值中**：不做也不会坏，只是压缩后模型要重新查一遍。

### P1-2 召回前的「这是不是一个问题」闸（抄 auto-memory）

**机制**：activation eligibility —— 「是不是一个提问/指令」比「有多相似」重要一个数量级。

**我们的现状**：`planTurnRecall` 只有一道 `userText.length < 8` 的闸。「继续」「好的可以」「往下做」这类 8 字符以上的续跑指令
照样触发检索，召回的必是噪声，还白占字节。

**最小实现**：纯本地判定，**不调模型**（C5/P7 都不许）。两道条件同时满足才跳过：
归一（去标点 / 语气词）后长度 < 12，**且**剥掉续跑词与虚词后剩余实义字符 ≤ 2。
只满足一道不跳，避免误杀。

**验收**：60 条 fixture 里续跑样本 0 召回；正常提问的 Recall@5 / MRR 不退化（`retrieval` 评测基线守住）。

**成本**：低（~25 行 + 1 套断言）。

> 落地进度（2026-10-20）：已进代码。`isContinuation()` 在 `lib/index.js`，随插件一起导出（纯函数，便于单测与面板诊断复用）。
> 它与原有的 `userText.length < 8` 那道闸**互补**：那道看原始长度，「好的，那就继续吧」原始 9 字符过得去，
> 归一后只剩虚词，由新闸拦下。`test/host.test.mjs` 用 7 条续跑 + 5 条短指令做表驱动验证。

### P1-3 整库快照（抄 meow 的 `VACUUM INTO` 思路 / prime 的「后悔药」）

**机制**：每次 dream 收尾或每日首次写入，把 `memories.json` + `portrait.json` 轮转快照，保留 7 份。

**为什么需要**：我们有版本链与 supersede 回滚，但那是**条目级**的。整个 `~/.dsh/storages/dsh-memory` 被误删
（或用户在面板点了清空）没有任何后悔药。meow 加这个是因为 #37 有真实误删事故。

**红线冲突**：快照只能放主库目录下（`backups/`），**不能放工作区**（D1）；失败必须静默，不能拖住 dream
（C5 的精神：别让收尾路径长出长活）。

**成本**：中低（store 里一个 `snapshotLibrary()` + 调用点 + 3 条断言）。

## 4. 我们已经领先、别退化

这一栏比 §3 重要：**别在追新的时候把已经做对的东西改坏。**

| 机制 | 我们 | 头部现状 |
| --- | --- | --- |
| 配置热生效（getter / 活读，不重建） | `store` 的 `qualityGate`/`security`/`review.days` 都支持 getter | meow v0.30.0 刚踩坑修完「设置不生效」（#26） |
| Agent 不能代审批 | 工具 `action` 枚举里**没有** approve/reject（只有 `/queue/approve` HTTP），结构上就绕不过 | memory-eternal v0.9.1 才补「注入红线禁止调 approve」 |
| 子代理不写记忆 | 已保持 | Claude Code 同款 |
| 简报字节稳定 + 会话冻结 | 有专门的 `briefing-stability` 套件守着 | meow/soul-md 是「静态 guide 文本恒定」，粒度比我们粗 |
| **抗压缩** | 简报/画像在 **system prompt 段**，压缩只动消息——我们天然活着 | meow / soul-md 的记忆是**消息**，压缩会吃掉，所以那两家必须整块回注 |
| 注入可预览（面板说的就是模型看的） | `/briefing-preview` 给的就是真注入字节 | mnemon 的「每轮记忆条」是事后看，不是事前预览 |
| 零 shell / 零 env / 零动态代码 | 能力只有 fs 读写 + 本机回环 | TOP20 里 9 个要 shell、13 个要 env |
| 派生链（源变了标脏） | 记忆 → 画像 → AGENTS.md 三层 | 只有 Veyra 做了类似的（代码锚点），我们是文档/记忆锚点 |

**唯一想补强的一条**：D4 要求「模型不能自封 trust」，我们靠结构挡住了，但**没对模型明说**。
在工具描述或「记忆纪律」段加一句：「草稿只能由用户在面板批准，不要尝试包括直接改 status 在内的任何等价绕过。」
一行字，把结构约束变成对模型也显式的约束。

## 5. 不抄

## 6. 分发补课（独立于功能，但比功能急）

三件都是「几分钟就能改、但决定有没有人装」：

1. **目录里的 install 命令还指着 v0.5.1 的 tarball**，而 `package.json` 已经是 0.6.0。目录读的是 Release 资产，
   我们得确认最新 Release 的 tag 与文件名，否则用户按目录里那条命令装到的是旧版。
2. **`downloads/version` 为 null**：142/266 有数据，我们没有。修法是让目录能解析到 npm 或最新 Release（`publish-npmjs.yml`
   已就绪，缺 `NPM_TOKEN`）。
3. **把能力声明写进 README 顶部**：`fs-read / fs-write / 本机回环 HTTP`，无 shell、无 env、无子进程、无出站网络，
   目录审计 **0 红线告警**。TOP20 里 9 个要 shell——这句话比任何功能列表都更能降低安装犹豫。
