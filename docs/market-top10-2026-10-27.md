## 0. 一页结论

1. **记忆市场一个月扩了 19%**（263 → 313 个插件），头部集中度基本没变（前 10 拿 47.2%），仍是头部通吃。
2. **本插件在 `memory` 分类第 192 名**，`downloads: null` / `npm: 0` / `★2`（10-18 快照时是 #143）。
3. **分发堵点已经定位到唯一一处：仓库没配 `NPM_TOKEN` secret**。
   `Publish to npmjs` 工作流早已存在、每次打 v* 标签都在跑，但守卫步骤判定「未配置」→ `Publish` 步骤 **skipped** →
   npmjs 上从来没有 `@bangbang-03/dsh-memory` → 市场 `probe-npm` 建不出映射 → `npm: 0`、`downloads: null` →
   目录退回展示我们条目里的 `tarball:` 字段，而那个字段指向 **v0.5.1**（落后三个补丁版）。
4. **而且 npmjs 上还没有 `bangbang-03` 这个账号**（`/-/org/bangbang-03` → 404），
   scope `@bangbang-03` 未开通——发布前得先注册，否则 `npm publish` 必然失败。
5. **上一轮「最值得抄的三件事」其实我们早就做完了**（路径 JIT / 注入可见化+成本 / 采用才强化），
   2026-10-19 的市场报告在这三点上已经过期，见 §3 纠正表。真正的短板只剩分发与可见度。

## 3. 纠正表：2026-10-19 市场报告已经过期的三处

上一轮我按 10-19 报告说「最值得抄的三件事」，逐条核对代码后发现**我们已经做完了**（工作树含未提交改动）：

| 项 | 10-19 报告的说法 | 代码现状 | 证据 |
| --- | --- | --- | --- |
| 路径 JIT（annkun 的触达激活） | P1-3「有 `files` 字段，没触发」 | **已实现**：`tools/pre-execute` 收集路径 → 命中记忆进本会话 stash → 下一个 `agent/pre-step` 尾部注入；触达后单调激活、跨 resume 保持 | `lib/index.js` 的 `pathRecall` / `pathRecallLimit` 配置、`noteToolPaths`、`pathRecallStash` / `pathRecallSeen` |
| 注入可见化 + 成本账（prime） | P1-6「面板看不到这次注入了什么」 | **已实现**：`GET /briefing-preview` 事前预览、注入审计（字节 + hash + 取了哪些 id + 挤掉了谁）、面板显示「最近一次路径注入 N 条 · ≈M token」、简报计量 `{mode, chars, count}` | `lib/api.js` 的 `GET /briefing-preview`；`lib/client.js` 的 `pathTailHint` / `injectionKind*` / `injectionDropped` |
| 采用才强化（StrataGate） | 「我们的 `useCount` 只记被取用」 | **已实现且更细**：曝光（`markExposed` → `exposedCount`）**不写** `useCount`、不抬高排序；只有显式 `markOpened`（被 get）与 `markCited`（答案引用 id）计入 `useCount` 并参与排序；体检还有「曝光 ≥3 但从未被打开或引用 → 最该复核」 | `lib/store.js` 的 `markExposed` / `markOpened` / `markCited`、排序里的 `usage` 因子、体检 `exposedButUnused` |

**结论：护城河比报告里写的更厚，缺的不是能力，是可见度。**
真正还欠市场的三样（按性价比排序）：

1. **发上 npmjs**（见 §4）——唯一能把 `dl: null` 变成真实数字的动作。
2. **上游条目的 `tarball:` 改成版本无关资产名**——现在市场装的是 0.5.1。
3. **README 补 npmjs 安装命令**——等第 1 步落地后再写，否则是虚假承诺（C7：README 是发布合同）。

## 4. 行动清单（按依赖顺序）

### 4.1 需要人手（仓库管理员 / 账号所有者）

1. **注册 npmjs 账号 `bangbang-03`** —— scope 名必须跟账号名一致（`registry.npmjs.org/-/org/bangbang-03` 现在是 404）。
2. **建 Automation token**（Read and write，publish 权限要覆盖该 scope）。
3. **加仓库 secret**：`Settings → Secrets and variables → Actions → New repository secret`，Name = `NPM_TOKEN`。
   或 `gh secret set NPM_TOKEN --repo BangBang-03/dsh-memory`。
4. **打下一个 v\* 标签**（`main` 上 `tools/release.mjs`）→ `Publish to npmjs` 会在标签推送时自动发布
   （注意：只在 **v\*** 标签触发；lab 线不发 npmjs，避免两条线版本号对不上）。
5. **验收**：
   - `npm view @bangbang-03/dsh-memory versions` 能看到版本；
   - `node tools/release-watch.mjs --version X.Y.Z` 的 `npmjs` 行显示「已发布」；
   - 市场下一次 probe 之后，条目 `npm` 变 1、`dl` 开始计数。

### 4.2 可以现在就做（不需要凭据）

6. **改上游目录条目**：`awesome-dsh-plugin` 仓库的 `data/plugins/BangBang-03__dsh-memory.yml`，
   把 `tarball:` 从
   `https://github.com/BangBang-03/dsh-memory/releases/download/v0.5.1/bangbang-03-dsh-memory-0.5.1.tgz`
   改成
   `https://github.com/BangBang-03/dsh-memory/releases/latest/download/dsh-memory-latest.tgz`

   理由（上游 `contributing.md` 明写）：`latest/download/` 只在请求时解析 `latest`，**文件名照字面取**——
   资产名带版本号的链接提交当天有效，下次发版就 404；要么资产名不带版本（我们仓库正好有 `dsh-memory-latest.tgz`，
   已验证 200），要么钉住 tag。
   ⚠️ 不要在 yml 里手写 `npm:` 字段——上游校验会直接拒绝。

7. **等 4.1 落地后补 README**：加 `dsh plugin --profile web add @bangbang-03/dsh-memory` 一行，
   并同步 C1 要求的四处包名（C7：README 是发布合同）。
